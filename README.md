# Mockify SaaS

Mockify is a cloud‑native platform that lets development teams define, version, and share OpenAPI contracts, automatically generate fully functional mock servers, and run contract‑based integration tests. Teams can publish contracts, spin up isolated mock endpoints for any environment, and integrate verification into CI/CD pipelines, reducing backend dependencies and accelerating front‑end development.

## Features

- OpenAPI contract repository with versioning
- One‑click mock server generation (HTTP/HTTPS)
- JWT‑based multi‑tenant authentication & role management
- Real‑time request/response inspector for mock endpoints
- Contract‑driven integration test runner (Pact‑like)
- CI/CD integration via GitHub Actions
- Dashboard with usage analytics and mock server health
- Export/Import contracts in JSON/YAML
- Rate‑limited public mock URLs for external stakeholders

## Architecture

The system follows a micro‑service‑style SaaS architecture. The backend is a single Go service using the Echo framework, exposing REST endpoints for contract management and mock serving. Persistence is handled by PostgreSQL accessed through Prisma (via the Go‑Prisma client). The frontend is a React SPA written in TypeScript, communicating with the backend via a thin GraphQL gateway (future‑ready). Docker containers encapsulate the backend, frontend, and database; Docker Compose is used for local development while Kubernetes manifests are generated for production. Authentication is stateless JWT, and all endpoints are protected by the auth middleware. Mock generation parses stored OpenAPI specs with go-openapi and creates in‑memory request matchers, eliminating the need for separate mock server processes.

## Testing

Backend unit tests (Go's testing package) cover handler logic, contract validation, and auth middleware. Integration tests spin up a Docker Compose stack, load sample contracts, and verify mock responses using HTTP test clients. Frontend uses Jest with React Testing Library for component unit tests and Cypress for end‑to‑end scenarios (login, contract CRUD, mock request flow). The CI workflow runs all test suites on every push, enforces coverage >80%, and fails the pipeline on linting or security scan issues.
